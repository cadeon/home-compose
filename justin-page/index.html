Identity & Access

Authentik serves as the centralized identity provider for the entire homelab. It handles authentication for all externally-facing services through two patterns:

Proxy Outpost (Gateway Pattern)

A dedicated Authentik proxy outpost pod sits in front of backend services. It intercepts requests, authenticates the user via Authentik's flow engine, and forwards authorized requests to the upstream service with identity headers. This is how Aperture is protected — the outpost terminates TLS, handles the auth challenge, and reverse-proxies to the Mac Mini.

Native OIDC (IdP Pattern)

Services with built-in OAuth/OIDC support (like Open WebUI) register as OAuth2 clients in Authentik. The service initiates the authorization code flow, Authentik handles consent and authentication, and the user's identity is asserted back to the service via ID token or userinfo endpoint.

Flows & Property Mappings

Authentik uses a flow-based authentication engine. The default provider authorization flow (default-provider-authorization-implicit-consent) handles the OAuth consent screen. Custom property mappings control what claims appear in ID tokens and what attributes are exposed via the userinfo endpoint.

Networking

DNS

DigitalOcean manages DNS for not-really.me. Two automation layers keep records current:

  • external-dns (in-cluster): Watches Kubernetes Ingress resources and creates/updates A and CNAME records in DigitalOcean automatically. When you deploy a new service with an ingress, DNS follows.
  • Cloudflare DDNS (NAS-side): A dynamic DNS updater keeps the root domain pointing at the current public IP, handling ISP NAT changes.

TLS

cert-manager provisions and renews Let's Encrypt certificates automatically. Two issuers are configured:

  • Let's Encrypt Production (YR2): Used for all external services. Certificates are stored as Kubernetes Secrets and mounted by Traefik.
  • Let's Encrypt Staging: Available for testing without hitting rate limits.

The NAS Traefik instance shares the same Let's Encrypt resolver pattern, so both the cluster and NAS services get valid certs from the same ACME account.

Ingress

Traefik serves as the ingress controller for the k3s cluster. Routes are declared as standard Kubernetes Ingress resources with host-based routing. Traefik's Kubernetes CRD provider watches these resources and updates its routing table in real time.

Storage

Two storage classes are available:

Storage ClassProvisionerUse Case
local-pathRancher Local Path Provisioner (built into k3s)Ephemeral workloads, stateless apps
nfsNFS Subdir External ProvisionerPersistent state (databases, caches, user data)

The NFS provisioner dynamically creates subdirectories on a Synology NAS share and provisions PV/PVC pairs on demand. When a PVC is created with the nfs storage class, the provisioner creates a corresponding directory, binds a PV, and the workload gets persistent storage — all without manual intervention.

Observability

A full Prometheus + Grafana stack runs in the monitoring namespace:

  • Prometheus: Scrapes metrics from the Kubernetes API server, kubelet, containerd, node exporter, DCGM exporter (GPU metrics), and individual service endpoints.
  • Grafana: Dashboards for cluster health, node resources, pod status, GPU utilization, and application-level metrics. Provisioned declaratively through Flux.
  • DCGM Exporter: NVIDIA Data Center GPU Manager exporter, deployed via the GPU Operator, exposing GPU temperature, memory usage, power draw, and utilization.

Secret Management

Bitnami Sealed Secrets encrypts Kubernetes Secrets using asymmetric encryption before they enter Git. The sealed-secrets controller running in the cluster is the only component that holds the private key and can decrypt them. This means the entire ripper-flux repo can be public — secrets are cryptographically bound to the cluster and useless outside it.

The Reflector operator syncs secrets across namespaces, enabling services in different namespaces to access shared credentials without duplicating sealed secrets.

NAS Services

The Synology NAS runs Docker Compose stacks managed through Portainer, with configs version-controlled in a separate home-compose Git repo. Traefik on the NAS shares the same Let's Encrypt ACME account as the cluster, so both sides get valid TLS. Services include Gitea, SearXNG, Calibre-Web, OpenSpeedTest, a private Docker registry, and several personal projects.
